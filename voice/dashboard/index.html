Two stopwatches, two different questions

Every clip on this page was timed. The scenarios where a quick reply matters were timed twice, because "how fast is the model" is two questions, and they have very different answers.

Whole call asks: how long until the finished audio file is back? Like downloading a song before you can press play. This is the Latency row in the metric table, and every clip in the study has it.
First audio asks: how long until the listener hears the first word? Like a phone call: the person on the line hears you start speaking; they do not wait for you to finish. This is the panel above, and it exists for the scenarios that need a quick reply.

On this page: elevenlabs-v3 says its first word after a median 1105 ms and hands back the finished clip after 2.8 s; gemini-3-1-flash-tts says its first word after a median 2318 ms and hands back the finished clip after 6.0 s. The two models are 1213 ms apart at the first word and 3.2 s apart at the finished file, and the same model is ahead on both. No streamed clip on either model reached the first word inside its scenario's ceiling.

How we measured it

  1. Same script, same voice, same model. For the 9 scenarios that need a quick reply, we asked each model to stream: send sound as soon as it has some, instead of the whole file at the end. Nothing else about the request changed.
  2. The clock starts when we send the request, before the connection is even open, so the network and the server's thinking time are all inside the number.
  3. The clock stops at the first piece of actual sound, not at a header or an empty message that arrives first.
  4. We keep listening until the clip ends, so the same clip also has a whole-call time. The two are stored side by side and never overwrite each other.
  5. Each of these scenarios sets a ceiling — 300 ms for the game line, 1000 ms for the conversational ones. A clip over its ceiling fails that gate like any other gate.
  6. Measured the same way on both models, from the same machine. This is the ordinary HTTP stream. It is not ElevenLabs' WebSocket real-time product, so the sub-second figures ElevenLabs publishes for that product are not what this panel measures.

What this page does and does not claim

  • All 116 clips are here, encoded to MP3; 24 kHz WAV originals on request.
  • A percentage is a rubric score, not an accuracy rate — 95% means 9.5 out of 10.
  • Quality is averaged over scored clips only; a gate failure counts against the gate rate.
  • Ranked on gates first, quality second, so failing more can never look like scoring higher.
  • Transcribed locally by medium, which shares a vendor with neither model.
  • Absent measurements show as “—”, never as zero; three batch runs carry timing but no score.
  • Served from: gemini-3-1-flash-tts Vertex AI · us-central1; elevenlabs-v3 ElevenLabs direct API · us; the judge Vertex AI · us-central1. Read back from the model configuration for runs that predate the field in the run record.
  • The judge is gemini-2.5-flash, a Google model — blinding hides the label, not the acoustic fingerprint, so the judged criteria carry that exposure, and it has never been checked against human listeners. The measured figures — word errors, timing, cost, gate rate — do not depend on it.
