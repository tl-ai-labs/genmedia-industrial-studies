# GenMedia video eval — Veo 3.1 vs Sora 2, text_to_video

Sibling of [`../image`](../image): the same modality-agnostic engine
(generate → deterministic checks → blind judge → score → report), with the
video lane in `runner/video/` instead of the image lane. Scenarios come from
`../assets/genmedia_validation_rubrics_with_industry_mappings.xlsx`
("Scenario bank" sheet, Video rows; scoring dimensions from the "Video" tab).

## Scope (v1)

20 scenarios — the two **asset-free** families only:

| Family | IDs | Settings |
|---|---|---|
| Cinematic / hero shot | VID-CIN-01..10 | 8s, 1080p, 16:9, audio off |
| Physics & action | VID-PHY-01..10 | 5–8s (run at 8s), 1080p, audio off |

The other four video families (advertising, avatars, image-to-video,
conversational editing) need reference assets or source clips — their task
names (`image_to_video`, `video_edit`, `avatar_dialogue`) are reserved in the
schema and out of scope for v1. They are still fully extracted:

* `scenarios/batches/video-v1.xlsx` — all **60** video rows of the sheet, the
  way `image/scenarios/batches/image-v1.xlsx` holds the image bank. Sheet
  `scenarios` is the runner's loader format (loads as 60 scenarios); `bank`
  carries every sheet column plus industry, task and runner params/checks;
  `industry_map` and `validation` record the 1:1 cross-check against the
  "Industry mapping" sheet (60/60, no gaps, prompts byte-identical).
* `scenarios/bank-video-pending/` — YAML for the 40 rows outside the v1
  bank, task set per family, with **no `inputs:` key** (a run that includes
  them is not rejected; reserved-task cells are skipped as n/a, never
  billed). `VID-AD-09` is the one that needs no asset and could run today.
* `configs/industry_map.yaml` — all 60 ids (Ads 30, Micro-drama 20, Gaming 10).
* `assets/bank/` — the frozen input assets those 40 rows need, built the way
  the image project built its bank: every file has a JSON sidecar with
  provenance + sha256, and the pending YAMLs declare them under `inputs:`.
  - **Stills (I2V / AD / AVA)** — `assets/make_bank_assets.py`: byte-for-byte
    reuse of the image project's synthetic bank (the fictional AURELO brand
    kit, synthetic portraits — never a real person — an interior, a
    landscape, a style plate) plus a handful generated with
    `gemini-3.1-flash-image` on Vertex for briefs nothing on disk matched
    (frame pairs/triples are edits of one frame, so the scene holds).
  - **Source clips (EDIT)** — `assets/fetch_edit_clips.py`: real footage
    from Pexels Video (free-to-use, commercial OK), 1280x720 landscape,
    chosen by title — **eyeball each clip before a paid run**, the match is
    not machine-verified. Source clips are never generated by a model under
    test, so no arm ever edits its own output. `VID-EDIT-10` is derived from
    the `VID-EDIT-08` result at run time and stays unwired.
  - `assets/wire_inputs.py` re-declares the `inputs:` from what is on disk.

## Recorded deviations from the sheet

* **1 seed, not 3.** The sheet asks 3 seeds per scenario; v1 runs one
  generation per scenario x model (the engine's cell has no repeat axis).
* **Gates are a validity floor, not the spec.** Deterministic gates reject
  unusable clips (decodes, duration in band, ≥720p); delivering below the
  requested 1080p/8s spec is *graded* by the measured `technical_compliance`
  criterion (weight 0.10) instead of scoring an automatic 0. `sora-2` tops
  out at 720p — the adapter records the downgrade and the criterion prices it
  (≈6.7/10 on resolution).
* **VID-CIN-10 names a "supplied still" that v1 does not supply** (the sheet
  marks it as needing a reference image despite sitting in this family). It
  ships for bank completeness with a warning in the file; consider excluding
  it from paid runs until `image_to_video` lands.
* **Rubric folds V6/V7/V13** (subject consistency, camera control, long-form
  coherence) into `prompt_adherence` + `temporal_consistency`; V14
  (safety/rights) is not judged — provider refusals are recorded as `refused`
  cells. Mapping documented in `configs/rubrics/video.yaml`.
* **Automated checks are container-level only.** The sheet's optical-flow /
  shot-boundary / particle-stability checks need decoded frames (ffmpeg or
  opencv) — deliberately excluded from v1's pure-python checks; see the
  Phase B note in `runner/video/checks.py`.
* **Judge media is not metadata-stripped.** Images are re-encoded before
  judging; mp4 has no safe pure-python re-encode, so clips reach the judge
  byte-for-byte and every judge row records
  `media.metadata_stripped: false`. Provider containers are not expected to
  embed identifying strings, but the caveat is recorded, not hidden.

Any subset of arms runs; total = the chosen arms' columns + judge. The
agreed pair (2026-08-28 weekly review: "Omni versus Seedance") is
**Omni Flash vs Seedance 2.5** — ~$53 at 720p or ~$107 at 1080p for the
20-scenario bank, judge included. Veo and Sora are parked as reference
arms (all four ≈ $188). All four arms are proven against the live APIs.
Seedance bills to a separate BytePlus ModelArk account (`ARK_API_KEY`,
see .env.example); on that platform the model must be activated
per-account, and "Free Credits Only Mode" must be OFF (Seedance 2.5 has
no free quota, so that mode refuses every call before the balance is used).

Runtime caveats, so the estimates are not mistaken for measurements:

* Per-clip times are published/benchmark figures (Veo 3 standard averaged
  ~2m41s per 8s clip in third-party benchmarks; OpenAI/Azure docs put Sora 2
  renders at ~1–5 min), **not** measured by this project — the run itself
  records the real per-clip latency in `telemetry.jsonl`, and the report
  prints p50/max per model.
* Wall clock assumes the configured throttles (`max_concurrency: 1` per
  provider; both arms can run in parallel with each other), so the full run
  takes roughly as long as the slower arm.
* The runner allows up to 900s per clip (`TIMEOUTS_S["video"]`) before a
  poll times out and is recorded as a visible `timeout` attempt.

**Both models ship `enabled: false`.** Flipping them on is a human decision:

* the remaining OpenAI credit (~$1.7) covers **two** Sora clips, not twenty;
* OpenAI retires the Videos API on **2026-09-24** — the Sora arm dies then;
* Veo bills the `ai-studies-console` GCP project via ADC.

## Running it

```
# offline test suite — no keys, no spend
pytest

# preflight only (rejects cleanly while models are disabled)
python -m runner.cli run --modality video --scenarios scenarios/bank-video

# after a human enables models in configs/models.yaml:
python -m runner.cli run    --modality video --scenarios scenarios/bank-video --budget 85.00
python -m runner.cli judge  --run <run-id>
python -m runner.cli report --run <run-id> --open
```

`scenarios/vid-00*.yaml` are three cheap smoke-test scenarios (4s, 720p) for
wiring checks — not part of the bank.

Honesty rules carried over unchanged from the image project: no fabricated
outputs, scores or costs; a missing key or failed call is a visible recorded
failure; runs are immutable — a correction is a new run. Video costs derived
from *requested* (not echoed) seconds are labelled `estimated` and the label
follows the number into the report.
