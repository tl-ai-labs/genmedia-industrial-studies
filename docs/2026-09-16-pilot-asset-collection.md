# Pilot asset collection — BGMI and Real Cricket 24

Date: 16 September 2026. Pilot step 4 (`docs/2026-09-15-gaming-pilot-bgmi-cricket.md`), plan section 5.

## What was checked on 16 September

- **Source posts.** The real prompts came from articles and prompt libraries, not from posts that attach the poster's own input file. None of the sourced cards has a usable input asset in its source post. (Curious Refuge and DataCamp embed their own demo clips, but those are their footage, not game content.)
- **Publisher press kits.** Neither Krafton India (krafton.in, battlegroundsmobileindia.com) nor Nautilus Mobile (nautilusmobile.com) publishes a press kit, media page or gallery. Krafton's pages carry only "© 2026 KRAFTON, Inc. All rights reserved." Nautilus links only to terms and privacy pages.
- **Store pages.** Google Play listings exist for both games (com.pubg.imobile, com.nautilus.realcricket) with screenshots. They are publisher property with no stated reuse terms, so they are recorded as the alternate route, not the first.
- **Own recording.** Both games run on a phone. This is the best route for every input and the only route for the Text-to-Image judge references. It needs a person with the games installed.
- **Generated.** Prepared and ready to run for every still and clip that is a model input. It needs a budget approval. Generated files are placeholders until an own screenshot replaces them.

## Generation fallback, ready to run

Scenario files: `image/scenarios/gen-inputs-gaming/` (one still per Image-to-Video and Image Editing card) and `video/scenarios/gen-inputs-gaming/` (one 8-second clip per Video Editing card). Model configs: `image/configs/models-gen-inputs.yaml` (Nano Banana Flash on Vertex plus GPT Image 2 medium, one tier from each family, neither an evaluated arm) and `video/configs/models-gen-inputs.yaml` (Sora 2, not an evaluated arm; Veo 3.1 as the fallback if Sora refuses).

After the run, the collector opens each generated still or clip, picks the cleaner one where two were made, copies it to the File path, and writes the model, prompt and date in Generation details. A generated input is replaced by an own screenshot whenever one becomes available, and the sheet says which was used in the run.

Gap to log: an input generated by one model family can favour that family in a later edit. The configs avoid the evaluated arms, but the families overlap (Gemini, OpenAI). Own screenshots remove the problem entirely.
