# Gaming Scenarios for Video and Image Evaluation — Collection Plan

Date: 14 September 2026 (updated 15 September 2026)

**Goal:** collect, create, review and finalise **more than 100 unique gaming
scenarios for video** and **more than 100 for images**. Over 200 in total.

| Lane | Task | What it means |
|---|---|---|
| Video | Image-to-Video | Turn one picture into a short video |
| Video | Video Editing | Change something in an existing clip |
| Image | Text-to-Image | Turn a written prompt into a picture |
| Image | Image Editing | Change something in an existing picture |

**The main requirement:** every scenario must be **genuinely about its
game**. It must use that game's real gameplay, characters, environments,
actions and look. A scenario that could belong to any game is not good
enough and gets replaced.

**Two roles:**

- **Collector** — studies each game, writes the scenarios, finds or creates
  the source picture or clip.
- **Reviewer** — checks that every scenario truly belongs to its game, scores
  it, removes duplicates and signs off the final list.

**Order of work:** video lane first, then image lane. The game briefs
(section 3) are written once and reused for both.

**Pilot first.** Before all 18 games, the plan is tested end to end on two
games, BGMI and Real Cricket 24, in both lanes. See
`docs/2026-09-15-gaming-pilot-bgmi-cricket.md`. The other 16 games start
only after the pilot passes.

## 1 · Step-by-step plan

| Step | What we do | What we end up with | Who |
|---|---|---|---|
| 1 | Agree on the 18 reference games and the four test-type lists (sections 2 and 4) | Approved game list and test-type lists | Reviewer |
| 2 | Study each game from its **official website** and write a one-page **game brief** (section 3) | 18 game briefs with source URLs, shared by both lanes | Collector |
| 3 | Find **real prompts people have shared in public** for each game, and build 7–8 scenario cards per game per lane from them and the brief (section 4) | 130–150 draft cards per lane, each with source link, source name and source assets | Collector |
| 4 | Get the input picture or clip for every card that needs one, from the same public source, an official source or our own recording. If none exists, create one (section 5) | Every card has a source file and full source details | Collector |
| 5 | **Relevance check:** go through every row in the sheet and confirm it is truly about its game. Replace or regenerate anything that is not (section 6) | Every row marked Relevant | Reviewer |
| 6 | Remove duplicates and generic scenarios (section 7) | Cards merged or removed, reason written | Reviewer |
| 7 | Score every remaining card (section 8) | A score for every card | Reviewer |
| 8 | Rank all cards and pick the best. Keep more than 100 per lane (section 9) | The final list per lane | Reviewer + Collector |
| 9 | Put the final list in the sheet and the folder (section 10) | One sheet and one folder per lane | Collector |
| 10 | Final check of everything (section 11) | Signed-off final set per lane | Reviewer |

Steps 3 to 10 are done once for video, then once for images.

**One rule for the whole plan.** A scenario is not finished until it has
five things: a filled-in scenario card, a real person's prompt with its
source link, source name and source assets (or a team-written prompt the
reviewer has approved), a source file with a source note (or a "no source
needed" mark for Text-to-Image), a Relevant mark from the reviewer, and a
reviewer score.

**Public and genuine.** Scenarios, prompts and inputs come from public,
genuine sources wherever one exists: community posts where people share the
prompt and the result, official websites and press kits, public reviews. We
record where each came from so anyone can check it.

## 3 · Understand the game first

Nobody writes a scenario for a game they have not studied. Before writing
anything, the collector spends about an hour on each game and fills in a
one-page **game brief**. The brief is the source of truth for every
scenario that follows, in both lanes.

### 3.1 Where to learn about the game

The **official website of the game** is the first and main source. Every line
of the brief must be traceable to it or to the publisher's other official
pages.

1. **The game's official website.** Game modes, maps, characters, weapons or
   equipment, vehicles, features, news posts and patch notes.
2. **The publisher's official store page** (App Store, Google Play, Steam).
   The official description and screenshots.
3. **The publisher's official help or support pages.** The exact names of
   modes, items and controls.
4. **Only for what no official page covers:** play the game, or watch the
   publisher's own gameplay videos, and mark that line of the brief as
   "observed in play".

Write the URL of every page used in the Sources row of the brief, with the
date it was read.

### 3.2 The game brief

One page per game, with these headings. Use the game's own words for names.

| Heading | What to write | Example (Fortnite) |
|---|---|---|
| **How a match works** | The basic loop from start to finish, in 3–4 lines | 100 players drop from the Battle Bus, gather weapons and materials, the storm shrinks the safe zone, last one standing wins |
| **Core actions** | What the player does most, named the way the game names them | Build walls and ramps, harvest materials with the pickaxe, glide, dance emotes |
| **Characters** | Playable characters, classes, skins, and how they look | Outfits change every season, cartoon proportions, expressive faces |
| **Environments and maps** | Named places and what they look like | The island, named locations, changes every season, bright and saturated |
| **Vehicles and items** | Things that move or get used | Cars, boats, shopping carts, shield potions, launch pads |
| **Signature moments** | The things people remember and share | The storm wall, a Victory Royale, a squad dance, a build battle |
| **Visual style** | Colours, lighting, shading, edges | Cartoon, thick outlines, bright colours, smooth surfaces |
| **Camera and view** | Where the camera is | Third person over the shoulder, first person in some modes |
| **On-screen display** | What is drawn on top of the game | Health and shield bars, minimap, material counts, storm timer |
| **Things this game does NOT have** | Common mistakes to avoid | No realistic blood, no first-person weapon reload animation in default mode |
| **Sources** | The official website URL, store page URL, any help page URL, and the date each was read | https://www.fortnite.com (read 2026-09-16); Google Play store page (read 2026-09-16) |

### 3.3 The rule that follows from the brief

Every scenario must use **at least two named things from the game brief**
(an action, a character, a place, a vehicle, a signature moment). If the
scenario does not, it is not about this game and is not written.

## 4 · How to write scenarios

### 4.1 Start from the game brief, then pick the test

Read the brief. For each item under "Core actions", "Signature moments",
"Vehicles and items" and "Environments", ask: what could an AI model get
wrong here? That question gives you a **test type** from the lists below.
Pick the test type, then write the scenario around that specific game moment.

**Rule:** each test type may be used **at most three times** in a lane's
final set, and never twice by games of the same kind.

#### Video lane

**Image-to-Video test types** (what the model must do from one picture)

1. One character does one action (throws, jumps, swings)
2. A sequence of actions in the right order (car stops, door opens, character gets out, runs to cover)
3. Something already flying in the picture keeps flying correctly (ball, grenade)
4. A dance or idle move that ends exactly where it started, so it can loop
5. Many small figures moving at once (troops, crowds, cars) without merging or multiplying
6. Only the camera moves, the scene stays still (circle around, push in, rise up)
7. Camera and subject both move
8. Non-stop forward travel with new scenery appearing (runner, road, tunnel)
9. A big effect over the whole scene (storm, explosion light) while a character does something
10. Speed effects (blur, smoke, sparks) that match how fast things are moving
11. Hands moving naturally, such as reloading a weapon in first person
12. Close-up of a face and hair moving (talking, wind, turning)
13. The art style must not change (anime stays anime, blocky stays blocky, hand-drawn stays hand-drawn)
14. Something being built block by block, earlier blocks never move
15. Water, fire, cloth or particles starting from a frozen picture
16. Two characters interacting (a punch and a block, a tackle, a pass)
17. Only the on-screen display animates (health bar, score, falling candies), the scene stays still
18. Tall phone-shaped (portrait) video
19. Lighting changes over time with nothing moving (sunset, headlights turning on)
20. Something appears out of darkness or fog with the right things in front and behind

**Video Editing test types** (what must change, and what must stay the same)

1. Swap the object in a character's hands (gun, bat, racket) with the hands adjusting
2. Change a character's outfit while they run and jump
3. Change the colour of one moving object, nothing else changes
4. Remove one moving thing (a troop, a car, a spectator)
5. Add one thing that fits in properly (casts a shadow, reflects, touches the ground)
6. Swap the background or map while the characters stay the same
7. Change the season (summer to snow) without changing shapes
8. Change the time of day or weather with correct light on people and objects
9. Change the whole art style (realistic to anime, 3D to pixel art) while movement stays the same
10. Change the camera (fixed to circling, chase view to inside-the-car view)
11. Slow motion at the moment of impact, then back to normal speed
12. Make the clip longer in a believable way
13. Make a choppy phone recording smooth
14. Make a low-resolution clip sharp without softening hard edges
15. Turn a tall clip into a wide one (or wide into tall) by filling in the sides
16. Blur player names, chat or kill feed everywhere they appear
17. Add an on-screen gauge that follows the action (speedometer, minimap, damage numbers)
18. Change only the text on screen (a label, a score)
19. Three edits one after another, nothing drifting between them
20. Undo a previous edit exactly

#### Image lane

**Text-to-Image test types** (what the model must get right from a prompt alone)

1. A full-body character with the right outfit details, weapon and pose
2. A wide shot of a named place with the right layout and landmarks
3. The art style is exactly right (anime, cartoon, blocky, hand-drawn, realistic) and nothing drifts
4. Readable on-screen display: health bar, minimap, score, timer, in the right places
5. Many small figures (troops, crowd, cars) with no duplicates and no merged bodies
6. Two characters interacting in one frame (a hit landing, a tackle, a handshake)
7. A vehicle with correct shape, wheels, windows and paint
8. A close-up of a weapon or item with correct parts and proportions
9. A named time of day or lighting mood (sunset over the map, night with neon)
10. Weather in the scene (rain, snow, fog) with correct effects on surfaces
11. An action frozen mid-motion (a drift, a jump, a swing) with believable body position
12. A top-down or isometric view of a base, board or map
13. First-person view with hands and weapon in the frame
14. A tall phone-shaped (portrait) picture such as a loading screen or poster
15. A facial expression or emote pose on a named character
16. Big effects frozen in place (explosion, elemental attack, hit sparks) without hiding the subject
17. Reflections and wet surfaces (rain on a track, a lake beside a base)
18. Clear depth: something in front, something in the middle, something far away
19. Correct hands: five fingers, holding the item properly
20. Text on an object in the scene (a jersey number, a shop sign, a car livery) spelt correctly

**Image Editing test types** (what must change, and what must stay the same)

1. Swap the object in a character's hands, with the hands adjusting
2. Change a character's outfit or skin, pose unchanged
3. Change the colour of one object, nothing else changes
4. Remove one thing (a troop, a car, a spectator) and fill the gap believably
5. Add one thing that fits in properly (shadow, reflection, touches the ground)
6. Swap the background or map while the character stays exactly the same
7. Change the season without changing any shapes
8. Change the time of day or weather with correct light on people and objects
9. Change the whole art style (realistic to anime, 3D to pixel art) while layout stays the same
10. Show the same scene from a different angle
11. Change a character's expression or pose only
12. Change only the text on screen (a label, a score, a name)
13. Blur player names, chat or kill feed
14. Make a low-resolution picture sharp without softening hard edges
15. Extend the picture sideways or upwards by filling in the edges
16. Change team colours or a car livery, everything else unchanged
17. Add one on-screen display element (a minimap, a damage number) in the right place
18. Three edits one after another, nothing drifting between them
19. Undo a previous edit exactly
20. Put a character from one picture into the scene from another picture

### 4.2 Use real prompts from real people

Wherever possible, a scenario is built from a **prompt a real person has
actually used and shared in public**, not a prompt we write ourselves. Real
prompts show what people really ask these models to do with game content,
and that is what we are evaluating.

**Where to look** (public, genuine sources):

- Community sites where people post the prompt together with the result:
  Reddit communities for AI video and AI images, Civitai, PromptHero,
  OpenArt, Lexica, and the community galleries of the video tools (Runway,
  Pika, Kling, Luma, Veo / Flow).
- Public posts on X, YouTube and Discord servers where the creator writes
  out the prompt they used.
- Game-community posts where players share AI edits of their own
  screenshots and clips, with the prompt included.
- Public reviews and write-ups of the models that quote the exact prompts
  they tested.

**What counts as genuine:** the prompt is quoted in full by the person who
ran it, and the post shows the result. Do not use prompts that are only
described ("I asked it to make the car drift"), prompts from prompt-selling
lists with no result shown, or prompts we cannot link to.

**What to record for every scenario**, on the card and in the sheet:

- **Source link** — the URL of the post.
- **Source name** — the site or community, and the poster's public username.
- **Source asset(s)** — the picture or clip the person used as input, and
  the result they posted, with a link to each.
- **Source prompt (verbatim)** — the prompt exactly as posted, unchanged.
- **Prompt origin** — Real.
- **Other source details** — the model they used, the date of the post, the
  post's licence or usage terms, and anything else that helps a reviewer
  find and check it.

**Turning a real prompt into our Prompt line:** copy it word for word. Change
it only if it names the game or a brand (replace the name with a plain
description, see 4.6) or if it names a real player. Write every change in
Other source details.

**When no real prompt exists:** if a test type the game genuinely offers has
no real prompt after a proper search, the collector may write one. Mark
**Prompt origin: Team-written**, say in Other source details where you
searched, and get the reviewer's approval before the card leaves Draft. Real
prompts rank above team-written ones when we pick the final set.

### 4.3 Game-specific, not generic

A scenario is **generic** if you could change the game name and it would
still make sense. Generic scenarios are not allowed.

| Generic (not allowed) | Game-specific (allowed) |
|---|---|
| "A character runs across a field" | "A player lands from the parachute on the Erangel-style grassland, unfolds a frying pan from their back and sprints to a jeep" |
| "A car drifts round a corner" | "A hypercar drifts through a neon Shanghai tunnel, hits the boost, and the nitro flame and blue speed lines kick in" |
| "Two characters fight" | "A fighter lands a Drive Impact: the screen flashes with a paint-splash effect, the opponent is knocked against the wall" |
| "A building gets destroyed" | "Twenty barbarians and five giants break through a stone wall and the Town Hall crumbles piece by piece" |
| "A picture of a soldier" (image) | "A full-body character in a level-3 helmet and ghillie suit, holding an AWM sniper rifle, standing on a rooftop in a grey military town" |
| "Make the car red" (image edit) | "Change the car's livery to the team's blue and white racing stripes; keep the tyre smoke, the tunnel and the reflections unchanged" |

**The generic test:** read the "Must change" line and the prompt. If it
would make sense for at least two other games on our list without changing
a word, rewrite it using named things from the game brief.

### 4.4 Where to find good moments in each game

Look in all five places for every game:

- **Real prompts people have shared** (section 4.2) — the first place to
  look. A real prompt tells you both the moment and the test.
- **The game brief** — every item under Core actions, Signature moments and
  Vehicles is a candidate.
- **Official trailers and launch videos** — the polished, best-looking shots.
- **Official screenshots on the store page** — the best pictures for
  Image-to-Video and Image Editing, and good references for Text-to-Image.
- **Everyday moments** — reloading, respawning, menus, replays. Models often
  struggle with these and they are easy to judge.

### 4.5 What "using the scenario card" means

A **scenario card** is a short form we fill in for every scenario, one card
per scenario. Think of it like an index card. It forces us to write down the
same details for every scenario, so nothing is vague and every scenario can
be compared with every other. In the sheet, each card is one row and each
line on the card is one column.

Here is a card with every line explained:

| Line on the card | What to write | Example |
|---|---|---|
| **ID** | A unique code. Video: `VID-GI2V-`, `VID-GEDIT-`. Image: `IMG-GT2I-`, `IMG-GEDIT-`. Then a number | `VID-GI2V-07` |
| **Game** | Which game the moment comes from | Asphalt 9 |
| **Type of game** | From the games table | Arcade racing |
| **Lane and task** | Video: Image-to-Video or Video Editing. Image: Text-to-Image or Image Editing | Video, Image-to-Video |
| **Test type** | The number and name from section 4.1 | I2V-10 Speed effects |
| **Title** | A short name, five words or fewer | Tunnel drift into nitro |
| **Game details used** | The named things from the game brief this scenario relies on (at least two) | Nitro boost, Shanghai tunnel track, hypercar class |
| **Input** | What we give the model. Image-to-Video: a picture. Video Editing: a clip. Image Editing: a picture. Text-to-Image: nothing, write "none" | A picture of a hypercar mid-drift in a neon-lit tunnel, tyre smoke frozen |
| **Source prompt (verbatim)** | The prompt exactly as the real person posted it, unchanged (see 4.2) | "asphalt 9 style hypercar drifting through the shanghai tunnel, nitro on, speed lines, tyre smoke, cinematic" |
| **Prompt origin** | Real, or Team-written (only with reviewer approval, see 4.2) | Real |
| **Prompt** | The prompt we actually run: the source prompt word for word, with only game or brand names replaced by plain words (see 4.6) | "The hypercar keeps drifting through the neon tunnel, the nitro flames ignite from the exhausts, blue speed lines streak past and the tyre smoke trails behind." |
| **Must change** | What we expect to move or change. For Text-to-Image, write what must appear | Car keeps drifting, nitro flames appear, speed lines and smoke trails grow |
| **Must stay** | What must not change. For Text-to-Image, write "n/a" | The car's shape and paint, the tunnel, the camera angle |
| **How to judge** | 3 to 5 things a person can check just by looking | 1) Speed of motion matches the blur  2) Smoke trails go the right way  3) Paint job unchanged  4) No smearing between frames |
| **Source link** | The URL of the public post the prompt and input came from. For Text-to-Image, also the reference picture we compare against | https://www.reddit.com/r/aivideo/comments/... |
| **Source name** | The site or community and the poster's public username | Reddit r/aivideo, u/example_user |
| **Source asset(s)** | Links to the picture or clip the person used as input, and to the result they posted | Input: poster's own screenshot (link). Result: posted clip (link) |
| **Source type** | Community post, Press kit, Store page, Own recording, Generated, or Reference only (Text-to-Image) | Community post |
| **Usage note** | The exact words from the source about how it may be used | "Public post; poster credited" or the press-kit wording |
| **Other source details** | The model the poster used, post date, any changes we made to the prompt, where we searched if the prompt is team-written | Model: Kling 2.1. Posted 2026-08-30. Changed "asphalt 9 style" to "arcade-racing style" |
| **Input file plan** | Where the input picture or clip will come from (section 5). This is about the file, never about the prompt | Poster's own screenshot from the same post; else own screenshot; else generated |
| **File** | Where we saved it | `assets/bank/gaming/video/VID-GI2V-07-still.png` |
| **Relevance** | Filled by the reviewer: Relevant, Replaced, or Regenerated (see section 6) | Relevant |
| **Status** | Draft, Sourced, Reviewed, Final, or Dropped (with reason) | Sourced |

If any line cannot be filled in, the card is not ready.

### 4.6 Prompt rules

**Real first.** The Prompt line comes from a real person's prompt (section
4.2). The rules below say how we adjust it, not how we invent it.

**No brand names.** Prompts describe the kind of game, never the game itself.
Write "third-person battle royale over a grassy island", not "BGMI". Brand
names make some models refuse, and make others copy protected designs. The
game name goes only in the Game line, for our own tracking. Named things from
the brief are fine to describe in plain words ("a frying pan on the back",
"a storm wall of purple energy").

**Every prompt must be genuinely different.** This applies across the whole
set, and especially inside one game. Rules:

- No two prompts may ask for the same action on the same kind of subject. "A
  car drifts" and "a red car drifts round a corner" is one prompt, not two.
- Inside one game, every scenario must be a **different moment** (not the
  same fight from a different angle), must **change a different thing**, and
  must **test a different test type**.
- Do not write a template prompt and change one word. If two prompts share
  most of their words, rewrite one of them or drop it.
- **Swap test.** Put two prompts side by side. If you could swap them and both
  scenarios would still make sense, they are the same scenario.
- **Across lanes.** A video scenario and an image scenario may share a game
  moment, but not a prompt. The image prompt describes a frozen instant; the
  video prompt describes what happens over time.

## 5 · How to find the original picture or clip

Every scenario has two sources: the source of the **prompt** (section 4.2)
and the source of the **input picture or clip** (this section). Both are
recorded on the card. Both must be public, genuine and linkable.

Text-to-Image scenarios need no input file. They need a **reference picture**
of the moment (from the same places below) so the judge can compare the
model's output against the real game. All other tasks need an input file.

### 5.1 Where to look, in this order

Stop at the first level that gives a usable file.

1. **The asset the prompt's author used**, when the post includes it and its
   origin is clear (their own screenshot or recording, or an official
   screenshot they link to). Record the poster as Source name and the asset
   link under Source asset(s).
2. **The publisher's press kit or media page.** Krafton, Garena, Epic Games
   newsroom, Riot, Moonton, Supercell, Nautilus Mobile, EA, Gameloft, Xbox
   Wire, HoYoverse, PlayStation, Rockstar Newswire, Mojang, SYBO, Capcom,
   Team Cherry, King. These give full-quality pictures and downloadable
   trailers with clear rules about use.
3. **The official store page.** Steam, App Store, Google Play, PlayStation
   Store, Xbox Store. Screenshots and trailers uploaded by the publisher.
4. **The official YouTube channel.** Use it only to find the moment and note
   the time. Do **not** download from YouTube. Write down the link and the
   timestamp, then look for the same trailer in the press kit.
5. **Record it ourselves.** Install the game on a team phone or PC and record
   the moment or take a screenshot. This is fully original and we control
   the quality. Note the device, settings and date.

### 5.2 If no original can be found, create one

A good scenario is never dropped just because the original picture or clip
cannot be found. Instead we **create** a suitable source:

- **For a picture (Image-to-Video, Image Editing, or a Text-to-Image
  reference):** generate one with our image models, using a prompt that
  describes the scene in genre terms and includes the named details from the
  game brief. Pick the sharpest, cleanest result. Save the generation prompt,
  the model used and the date.
- **For a clip (Video Editing):** generate one with our text-to-video models
  in the same way, or record our own gameplay. Make sure the clip clearly
  contains the thing the edit will change.
- Mark **Source type: Generated** (or **Own recording**) on the card, and
  write the generation prompt or recording details in the Source link line.
- A generated source must pass the same quality check as any other (section
  8, question 3) and must still look like the game it stands for. If we
  cannot make a good enough one, try once more with a different prompt before
  dropping the scenario.

### 5.3 Never use

- Compilations, re-uploads and reaction videos where the original creator
  is unknown.
- Screenshots from wikis, fan sites or image search with no named creator.
- Anything watermarked, re-encoded or cropped by someone other than the
  creator.
- Anything we cannot link back to a public page with a named source.

A community poster's own screenshot or clip is fine when the post is public,
the poster is named, and the link is recorded.

### 5.4 What to save for every source

| What | Example |
|---|---|
| Source link | `https://www.reddit.com/r/aivideo/comments/...` or `https://press.example.com/game/media` |
| Source name | Reddit r/aivideo, u/example_user; or "Krafton press kit" |
| Source asset(s) | Input: poster's own screenshot (link). Result: posted clip (link) |
| Source type | Community post / Press kit / Store page / Own recording / Generated / Reference only |
| Date we got it | 2026-09-16 |
| Usage note | Exact words from the source, e.g. "Assets may be used for editorial and review purposes", or "Public post; poster credited" |
| Other source details | Model the poster used, post date, changes we made to the prompt, where we searched if team-written |
| Original file name | `game_screenshot_04.png` |
| Size / length | 3840×2160 / 12 seconds |
| Our file | `assets/bank/gaming/video/VID-GI2V-07-still.png` |
| Timestamp (clips only) | 00:42–00:50 |
| Generation details (generated only) | Prompt, model, date |

Files go in `assets/bank/gaming/video/` or `assets/bank/gaming/image/`,
named by scenario ID. The folder lives on the shared drive, not in git,
because the files are large. The sheet records the path.

### 5.5 A note on rights

Game pictures and footage belong to the publisher. Using them for our own
internal evaluation is normally allowed by the publisher's press or content
rules, but we copy the exact wording into the Usage note so we can show it
later. Anything marked "no redistribution" is fine to use internally but must
not appear in a client-facing report without a check.

## 6 · Relevance check: is every scenario truly about its game?

This is the most important review step. Once the scenarios are in the sheet,
the reviewer goes through **every row** with the game brief open beside it.

### 6.1 For each row, ask

1. Does this moment actually happen in this game? (Check the brief and, if
   unsure, the official wiki or a gameplay video.)
2. Does the scenario use at least two named things from the game brief?
3. Are the characters, places, vehicles and effects the ones this game
   really has, and do they look the way the game draws them?
4. Would a regular player of this game recognise the moment straight away?
5. Does it pass the generic test in section 4.3?
6. Is the prompt a real person's prompt (Prompt origin: Real) with source
   link, source name and source assets recorded? If it is team-written, has
   the reviewer approved it?

**All six must be yes.** Then mark the Relevance column **Relevant**.

### 6.2 If any answer is no

1. **First, try to replace it.** Go back to the game brief and find a real
   moment in this game that tests the **same test type**. Rewrite the card.
   Mark Relevance **Replaced** and note what it replaced.
2. **If no suitable moment exists in this game for that test type,** pick a
   different test type that this game genuinely offers and write a brand new,
   high-quality scenario for it. Mark Relevance **Regenerated**. Check that
   the new test type does not push any test type over its limit of three.
3. **Never leave a weak or generic scenario in place** because it is easier.
   The game must keep its minimum count, so a dropped row always gets a
   replacement.

### 6.3 Common mistakes to look for

- A moment borrowed from a similar game (a first-person reload in a game that
  is only third person; realistic blood in a cartoon game).
- A vehicle, weapon or ability the game does not have.
- The wrong look (a realistic prompt for an anime game).
- The wrong view (top-down for a game that is always over the shoulder).
- A generic scene with the game name attached ("a character walks through a
  forest").
- For images: a character in an outfit or with a weapon that is not in the
  game, or a map layout that does not match the real place.

## 7 · How to find and remove duplicates and generic scenarios

Two scenarios are duplicates when they have **the same test type and the same
kind of subject**, even if they come from different games. "Recolour a car"
in Asphalt and "recolour a car" in Forza is one scenario, not two.

Do this in order:

1. **Sort all cards by test type.** Any test type with more than three cards
   has duplicates. Any test type used twice by the same kind of game has a
   duplicate.
2. **Compare the "Must change" lines in pairs.** If you could swap the two
   lines and both cards still make sense, they are the same scenario. Keep
   the one with the better source and drop the other.
3. **Compare the "Must stay" lines.** Two cards that change different things
   but test the same thing staying still are small variations of each other.
   Merge them into one.
4. **Compare the prompts** using the swap test from section 4.6. Same result:
   keep one, drop one. When two real prompts from different people ask for
   the same thing, keep the one with the fuller source record.
5. **Run the generic test** from section 4.3 on anything that survived. A
   scenario that fits two or more other games goes back to the collector for
   a rewrite from the game brief.
6. **Check against the scenarios we already have.** The existing video
   scenarios in `video/scenarios/bank-video-pending/` and the existing image
   scenarios in `image/scenarios/bank-image/` and `image/scenarios/bank-edit/`
   already cover the everyday cases (subtle motion, product turntable,
   background swap, remove an element, change time of day, recolour one
   object, edit text, undo an edit, and so on). A gaming card on one of these
   must test it in a clearly different way (different look, different camera,
   many more moving things), or it is dropped.
7. **Write the reason** for every drop in the Status line so nobody adds it
   back next week.

## 8 · How to select the best scenarios

Score every card on seven questions, 1 to 5 each. The reviewer scores alone
first. Then reviewer and collector go through any disagreements together.

| # | Question | 5 means | 1 means |
|---|---|---|---|
| 1 | Is it genuinely about this game? | Uses named actions, places or characters from the brief; a player would recognise it instantly | Could be any game |
| 2 | Is it unique? | Only card of its test type for that kind of game | Same as another card |
| 3 | Does it look good? | Sharp, well lit, clear subject | Blurry, cluttered, dark |
| 4 | Is it useful for testing AI? | A weak model will clearly fail it, a strong model will clearly pass | Every model would pass, or every model would fail |
| 5 | Is the task clear? | Obvious which task it is and what the input is | Could be either, input unclear |
| 6 | Is the source reliable? | Public, genuine and linkable: a real person's prompt with source link, source name and source assets recorded; input from the same post, a press kit, or our own recording | Prompt team-written without approval, or source not linkable, or unknown |
| 7 | Is it different enough from its neighbours? | Different look, camera and subject from the cards next to it | Shares two of those three |

**Keep** if the average is 4 or higher, **question 1 scores 4 or 5**, and no
question scores below 3.
**Fix and re-score** if one question is below 3 and it can be fixed (a weak
source can be generated; a generic scenario goes back to the brief).
**Drop** everything else, and write the reason.

Extra checks the reviewer does on every card:

- "How to judge" has 3 to 5 items, and each one can be seen in the output
  without extra information.
- Nothing on the card names an AI model or company, so it can be judged blind.
- Nothing sensitive: no real-money gambling screens, no real player names
  visible except in the "blur the names" scenario.

## 9 · How to prepare the final set

### 9.1 Collect more than we need

Aim for **130–150 draft cards per lane** (7–8 per game). More is better. A
bigger pool means the final set is the best of many, not just everything we
found.

### 9.2 Rank everything

After the relevance check, duplicate removal and scoring:

1. Sort all cards by average score, highest first.
2. Break ties with question 1 (about this game), then Prompt origin (Real
   above Team-written), then question 2 (uniqueness), then question 4
   (useful for testing).
3. Walk down the list from the top, adding cards to the final set, and skip a
   card if adding it would break any of the balance targets below.
4. Keep going until the balance targets are met and the count is **more
   than 100**. Aim for 100–120 per lane. Cards scoring 4.5 or higher that do
   not fit go on a "reserve" list for a later round.

### 9.3 Balance targets (per lane)

| Check | Target |
|---|---|
| Total | More than 100. Aim for 100–120 |
| Split between the two tasks | 50–60 of each |
| Per game | 5–7 scenarios (no game above 7, none below 5) |
| Per kind of game | Shooters at most 24. Sports, racing, adventure/action, strategy/arena, sandbox/runner, 2D/casual: at most 15 each |
| Per test type | Used at most three times, never twice by the same kind of game |
| Looks | Realistic, stylised, cartoon, anime, blocky and hand-drawn all present |
| Views | Third person, first person, top-down, TV style, chase view and side view all present |
| Portrait | At least 10 tall phone-shaped scenarios |
| Relevance | Every card marked Relevant, Replaced or Regenerated by the reviewer |
| Sources | Every card has a source link, type and usage note |

If a game falls below 5 after ranking, go back to its game brief and write
new scenarios for it. If a test type has not been used at all, find one
scenario for it before adding a third card to any crowded test type.

## 10 · How to organise the final set

One sheet, one folder and one set of scenario files **per lane**.

**The sheets**
`docs/sheets/gaming-scenarios-video.xlsx` and
`docs/sheets/gaming-scenarios-image.xlsx` (kept out of the scenario folders because
the runners try to read any spreadsheet they find there as a scenario list), one row per
scenario, sorted by Task then Game. Columns, in this order:

The Scenarios tab follows the **Scenario bank** sheet of
`genmedia_validation_rubrics_with_industry_mappings.xlsx` exactly: a title
in row 1, a note in row 2, the header in row 4, the first three columns and
the header frozen, and a filter on the header. Columns A to N are the 14
Scenario bank columns, in the same order and with the same names, so the
runner and the raters read gaming rows the same way as every other row.
The gaming columns follow from column O.

```
Scenario bank columns (A-N, unchanged from the reference):
Scenario ID | Modality | Use case family | Scenario | Capability under test |
Prompt / input brief (verbatim for the runtime) | Input assets required |
Asset source | Link | Run settings | Adherence clauses — check each |
Automated checks | Human-scored dimensions | Pass criteria

Gaming columns (O onward):
Game | Type of game | Task | Test type | Game details used | Must change |
Must stay | Source prompt (verbatim) | Prompt origin | Source link (prompt) |
Source name (prompt) | Source asset(s) | Source type (prompt) | Usage note |
Other source details | Input file plan | File | Size or length | Timestamp |
Generation details | Relevance | Reviewer score | Status
```

How the card maps onto the Scenario bank columns: Title → Scenario; Test
type → Capability under test (short phrase); Prompt → Prompt / input brief;
Input → Input assets required ("none" for Text-to-Image); How to judge →
Adherence clauses; Use case family, Run settings, Automated checks,
Human-scored dimensions and Pass criteria are filled per task from the
reference's own conventions (for example Image-to-video scores V1, V2, V3,
V4, V6, V10, V14). Text-to-image cards that fit no reference family use a
new family, "Game environment & action".

The three "(prompt)" columns say only where the **prompt** came from. A card
with no prompt source shows **NONE FOUND** in all three and its Status reads
**BLOCKED: no prompt source**. Where the **input picture or clip** will come
from is a separate column, **Input file plan**, so the two are never mixed.

Each sheet has a second tab, **Game briefs**, holding the same 18 one-page
briefs from section 3, so anyone reviewing a row can check it against the
game without leaving the sheet.

**The folders** `assets/bank/gaming/video/` and `assets/bank/gaming/image/`
on the shared drive, one file per scenario named by its ID, plus a short
README with the date and the drive link.

**The scenario files** in `video/scenarios/bank-video-gaming/` and
`image/scenarios/bank-image-gaming/`, one per row, in the same format as the
existing scenario files in each lane so the runner can read them without
changes. IDs run `VID-GI2V-01`, `VID-GEDIT-01`, `IMG-GT2I-01` and
`IMG-GEDIT-01` onward.

## 11 · Final review checklist

The reviewer ticks every line for each lane before that lane's set is called
final.

- [ ] Every game has a completed game brief on the Game briefs tab, built from the game's official website, with the URLs and dates in its Sources row.
- [ ] Every row's Prompt origin is Real, or Team-written with the reviewer's approval noted in Other source details.
- [ ] Every row has Source link, Source name, Source asset(s) and Other source details filled, and every link opens to a public page.
- [ ] Every row is marked Relevant, Replaced or Regenerated, and every row uses at least two named things from its game brief.
- [ ] No row fails the generic test. Every prompt was read with the game name covered and still clearly belongs to one game.
- [ ] No two cards share test type and kind of subject. Sorted by test type and read in pairs.
- [ ] No two prompts pass the swap test, within the lane and across lanes for the same game moment.
- [ ] The lane has more than 100 scenarios. Every game has 5–7 cards. Every kind of game is inside its cap.
- [ ] All six looks and all six views are present.
- [ ] Every card scores 4 or higher on average, 4 or 5 on "about this game", and none below 3 on any question.
- [ ] Every card has a source link, source type, usage note and file (or a reference picture for Text-to-Image). Generated sources have their generation details.
- [ ] Every prompt is free of game names. The Prompt column was searched for all 18 names.
- [ ] Every "How to judge" list has 3–5 items you can see in the output.
- [ ] Every file opens, matches its ID, and is the size recorded.
- [ ] Every scenario file loads without errors.
- [ ] Reserve cards (score 4.5+, not in the final set) are listed at the bottom of the sheet.
